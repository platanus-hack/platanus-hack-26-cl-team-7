Public datasets

Zanbil shop logs

CC0 · 3.3 GB
What
~10 million nginx access-log lines from a real Iranian online shop (zanbil.ir), 2019.
Fields
IP, time (1 s), method, path + query, status, bytes, referer, User-Agent.
Labels
None. A labeled copy marks attacks by keyword rules.

Why: real humans at real volume, in exactly the default log format a small site has. It is the base for the false-alarm and 1-in-10,000 tests.

Limit: another site's routes, so it can't test the route-list rule. Bots are mixed in unlabeled.

Zenodo web robot logs

CC BY 4.0 · 3.2 GB
What
4,091,155 requests from a university library search site, March 2018. 27,061 IPs, 3,441 User-Agents.
Fields
Raw anonymized log requests (JSON), plus per-session feature tables (CSV).
Labels
Sessions labeled human or robot.

Why: the only large public set with human-vs-robot labels. It checks the "sure human" filter and the pace rules on real people.

Limit: the last part of each URL is hashed, so file and payload rules can't run on it. Robots here are crawlers, not attackers.

CSIC 2010

Research set
What
36,000 normal and 25,000+ attack HTTP requests to a test shop app.
Fields
Full requests: method, URL, headers and body.
Labels
Normal or anomalous: SQL injection, XSS, path traversal, CRLF, buffer overflow, hidden-file probes.

Why: outside ground truth for the critical-flag rule (R3). Nobody on the team wrote these labels.

Limit: generated traffic from 2010, one app, no sessions or timing.

Transluce agent activity

No license · internal only
What
URL-scan reports from 2026 that real AI agents made: 6,467 with strong evidence, 31,182 with weaker evidence.
Fields
Scanned URLs and timestamps.
Labels
Agent-like activity, as judged by Transluce.

Why: the only real record of how AI agents probe. Example: 12 probes of 7 attack types in 28 s. It checks that our lab agents behave like real ones.

Limit: not traffic to our site, and no request headers. No license, so we use it but don't redistribute it.

SecLists

MIT · lists
What
The standard word lists that scanners use: paths, sensitive files, payloads, sorted by technology.

Why: it feeds rule R3 (sensitive files and payloads) and the scanner runs. The paths an attacker tries are mostly on these lists.

Limit: lists, not traffic. Nothing to score against.

Data we record ourselves

Volunteers on Harold's site

Must have

People use the site normally through Caddy. This is the only data with real humans and our routes, full headers and millisecond timing, so the route-list rule (R1) can only be tested here. Target: 30 or more sessions.

Scanner runs

Must have

ffuf, nuclei and nikto against the site through Caddy, plus CSIC payloads replayed into it. These give labeled probing sessions on our own routes for rules R1 to R3.

AI-agent lab runs

Later, by you

CAI, PentestGPT and hackingBuddyGPT against our lab only. This is the only source that covers every column above. Until it exists, AI-agent recall is "not measured".

Rule fixtures

Hand-written

Tiny made-up sessions at each rule's limit, for example exactly 10 and 11 endpoints in 60 s. Used by the pytest rule tests.

Which data feeds each test level

1 · Rule tests

Rule fixtures only. Each rule fires at its limit and not below it.

2 · Labeled replay

Volunteers, scanner runs, CSIC, Zenodo humans and robots, Zanbil confirmed humans. Gives precision, recall and requests before the verdict.

3 · Realistic rate

Zanbil volume with scanner sessions mixed in at 1 in 10,000. Gives the false alarms a client would really see.

What no public data gives us

  • Bank traffic: no public set exists, because banks don't release logs. Each client's own logs replace it.
  • AI agents on our routes, with full headers: only the lab runs give this.
  • Large-scale real humans on our own routes: volunteers are few, so the report shows the session count next to every rate.
