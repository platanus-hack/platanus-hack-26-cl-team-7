Version 0 flow

The 3 rules

RuleFires whenVerdict.
R1 Contract exits.5 or more requests to routes outside the route list in 5 minutes.Probing.
R2 Endpoint breadth.More than 10 different endpoints in 60 seconds. An endpoint is a route pattern, so /api/users/{id} counts once.Probing.
R3 Critical flag.One request for a sensitive file such as /.env, or a known attack payload in the path or query.Probing, critical.

The route list is a YAML file. Harold gives the first version. The crawler and the evidence sum of draft 9 replace these simple rules in version 1. All numbers above are starting values. Step 6 tunes them on data.

The floor also applies. No new suppression comments, no empty stubs, no skipped tests and no weaker limits in the same change as the code that failed them. An exception needs an owner and an end date.

Accuracy tests

The tests have three levels. Each level answers a different question.

1 Rule tests
Does each rule fire at its limit and not below it? Example: 11 endpoints in 60 seconds fires R2, and 10 does not. These are pytest tests with fixed inputs.
2 Labeled replay
How accurate is the engine on real sessions? make eval sends labeled log files through the engine and scores each session against its label.
3 Base rate test
How many false alarms does a client see? The test mixes attack sessions into human sessions at 1 in 10,000.

Three rules keep the score honest. The test set is split by session, never by request. The tune set sets the thresholds, and a separate test set gives the final score. A hash file locks the test set, so a change to it shows in review.

Build order

Risks

  • R1 3 rules miss slow AI agents High Version 0 targets probing only. Version 1 adds the client checks and the evidence sum.
  • R3 Thresholds fit the test set High Tune on the tune set only. The hash lock shows each change to the test set.
  • R2 Too few real human sessions Medium Volunteers plus sure-human Zanbil sessions. The report shows the session count next to each rate.
  • R4 The file size limit splits code badly Low An exception with an owner and an end date covers a real case.

Which language for version 0?

Draft 9 used Rust for the live path.

  • Python now, Rust after a load test RecommendedCaddy carries the traffic, so the engine only reads a log. Rust replaces the engine only if the load test shows a need.
  • Rust nowFast from day 1. More build time before the first result.

What file size limit?

Small files are easy to read and review.

  • 200 lines, 300 for tests RecommendedA reviewer reads one file in one pass. Each module keeps one job.
  • 400 lines, 600 for testsFewer files. Files can hold more than one job.

Block or warn on a failed check?

An agent writes much of the code.

  • Block RecommendedNobody reads a warning in an unattended run.
  • Warn for 2 weeks, then blockLess friction at the start. Some weak code gets in.

Done when

  • make check passes. It also fails on a source file of 201 lines, which proves that the size rule works.
  • docker compose up starts Caddy, the demo site, the engine and the dashboard.
  • An ffuf run against the proxy shows one probing verdict on the dashboard in less than 2 seconds.
  • make eval prints the confusion table and all metrics in the accuracy table, and writes eval/report.json.
  • CI fails when precision or recall falls more than 0.5 points below eval/baseline.json.
  • eval/testset.lock holds a SHA-256 hash for each test file.

Terms

Caddy
An open-source web server and proxy that writes JSON logs with headers.
Contract exit
A request for a route that is not on the route list.
Precision
The share of probing verdicts that match the label.
Recall
The share of real probing sessions that the engine finds.
Tune set, test set
Two separate parts of the labeled data. One sets the thresholds and one gives the final score.
CI
Continuous integration, the checks that run on each push.
